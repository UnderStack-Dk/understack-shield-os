# Security policy

## Reporting a vulnerability

Do not file public issues for suspected vulnerabilities, exploit paths, insecure defaults, or sensitive architecture weaknesses. Use GitHub's private security reporting feature for this repository when enabled, or contact the repository owner through the organization’s established private channel.

Provide a clear description, affected documentation or future component, impact, reproduction details where safe, and any suggested mitigation. Do not include secrets or personal data.

## Scope and expectations

The project is pre-development. Security reports about repository configuration, documentation exposure, or future design risks are welcome. Response targets and supported release versions will be defined once the project has an implemented release process.

## Disclosure

Please allow time for triage and coordination before public disclosure. We will acknowledge reports, assess impact, and agree on a disclosure timeline when practicable.
