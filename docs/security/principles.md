# Security principles

1. **Zero Trust local:** local origin does not automatically establish trust.
2. **Least privilege:** grant the smallest capability for the shortest useful time.
3. **Deny by safe default:** unknown or high-risk boundary crossings require explicit policy.
4. **Defense in depth:** no single control is treated as sufficient.
5. **Contain before cure:** isolate suspected activity and preserve evidence where safe.
6. **Verified state and recovery:** protect the boot chain and make known-good recovery practical.
7. **Explainability:** security actions should carry human-readable reasons and evidence references.
8. **Secure evolution:** updates, configuration changes and exceptions need reviewable provenance.
